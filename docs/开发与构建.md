# 开发与构建

Electron 管理窗口、托盘、开机启动和系统通知。界面通过应用内部 `paperdesk://app` 地址访问本地 Python 后台，稿件保存在 SQLite 中。

Mac 和 Windows 均构建完整离线安装包，包含 Python、Node.js、Playwright 和配套浏览器组件。构建时从 Playwright 官方下载服务取得与锁定版本匹配的组件，随安装包放入 `runtime/browsers/`，启动时直接使用。组件缺失时构建会报错。

## 构建

需要 Node.js 24 和 Python 3.13。

```sh
npm ci
python3 scripts/prepare_runtime.py macos-arm64
npm test
npm run package:mac
npm run verify:package
npm run smoke:package
npm run release:collect
```

Windows 在 Windows 电脑上执行 `python scripts/prepare_runtime.py windows-x64`，再执行 `npm run package:win`。Mac 使用 `npm run package:mac`。两端均包含 Chromium、无界面 Chromium、Firefox 和 FFmpeg；Windows 另包含依赖检查工具。

`npm run release:collect` 汇总 Mac 和 Windows 离线安装包到 `release/`。

`build/runtime/`、`build/work/`、`build/test-results/` 和 `release/` 为本地生成目录，不提交到仓库。图标源文件位于 `assets/`，修改后运行 `node scripts/make-icons.cjs`。

## 开发检查

- `npm test`：后台、桌面逻辑和读取器测试。
- `node scripts/smoke-desktop.cjs`：在独立空白数据目录运行桌面流程。
- `node scripts/smoke-browsers.cjs`：启动两个浏览器引擎。
- `npm run smoke:package`：检查本机已打包应用。
- `npm run verify:package`：检查包内运行组件、架构和数据隔离。
- `node scripts/audit-package.cjs windows-x64`：检查 Windows 离线包的组件完整性。
- `node scripts/smoke-first-launch.cjs`：以空白数据目录和不可用的下载代理检查包内浏览器、首次启动与再次启动。
- `node scripts/smoke-offline-windows.cjs`：在独立 Windows 测试环境实际安装离线包，以不可用的下载代理检查安装、两个浏览器引擎、首次启动与再次启动。

`PAPERDESK_TEST_EXECUTABLE` 指定待测应用，`PAPERDESK_TEST_RUNTIME` 指定其 runtime，`PAPERDESK_TEST_COMPONENTS_DIR` 指定浏览器组件目录。正常使用时无需设置这些变量。

GitHub Actions 在 Pull Request 或手动触发时构建并检查 Mac 与 Windows 离线安装包。

## 版本与发布

公开版本采用 `1.0`、`1.1`、`2.0` 的形式；`package.json` 使用构建工具要求的三段格式，例如 `1.0.0`。安装文件、界面和发布页显示两段版本号。

更新版本时同步 `package.json`、锁文件、`updates.json` 和发布说明。`updates.json` 中提供对应版本的 HTTPS 下载链接。完成构建后，在 GitHub Releases 创建 `v1.0` 形式的标签并上传 Mac 和 Windows 两个离线安装文件。

组件安装参考 [Playwright 浏览器管理](https://playwright.dev/docs/browsers#managing-browser-binaries)，Windows 安装流程使用 [electron-builder NSIS 扩展](https://www.electron.build/nsis/)。
